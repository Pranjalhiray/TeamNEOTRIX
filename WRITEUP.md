# Technical Write-up
**AI-Powered Monitoring & Analysis of Bitcoin Transaction Traffic — SIH 2026 PS-5 (NTRO)**

## 1. Approach

We built a five-stage offline pipeline: **ingest → correlate (graph) → detect
(4 AI/ML models) → fuse & rank → visualize**. Every stage is a plain Python
function in `src/pipeline.py`, cached once by `src/build_artifacts.py`, and
served through a Streamlit dashboard (`app.py`) that needs no internet at run
time.

**Ingestion:** CSV tables are the primary feed; we also demonstrate parsing
the dataset's nested-JSON form (`sample_nested.json`, matching the PS's
`input_addresses[]`/`input_amounts[]` array-field spec) in the notebook.

**Correlation:** we build a single graph with three node types — `ip:`,
`tx:`, `wallet:` — linking every broadcasting IP to the transaction it sent,
and every transaction to the wallets it spent from / paid to. Network-layer
fields (`src_ip`) are enriched with a real, open-source, fully offline GeoIP
database (`geoip2fast`, MIT-licensed, ships its own IPv4/IPv6 tables inside
the pip package — no MaxMind account or separate download needed), directly
satisfying the PS's "integrate open source downloadable Geo IP database"
requirement while staying offline.

## 2. Model choice, per focus area

| Focus area | Model | Why this model |
|---|---|---|
| **Entity Clustering** | Union-Find (common-input-ownership) + TruncatedSVD graph embedding (address × transaction incidence matrix) + K-Means | Union-Find is the textbook, zero-parameter first pass real chain-analysis tools use. We add an embedding step because — see finding below — the raw heuristic under-performs on this dataset; SVD-over-incidence is a fast, dependency-light stand-in for node2vec/DeepWalk that needs no GPU and trains in seconds. |
| **Anomaly Detection** | Isolation Forest | Unsupervised, doesn't require the `is_anomaly` label to train (only to evaluate), handles the mixed numeric feature set well, and gives a continuous outlier score rather than a hard cutoff. |
| **Peeling-Chain / Mixing Detection** | RandomForest (multi-class) on tx features + graph in/out-degree, **plus** a rule-based chain-walk sequence detector over the tx-flow graph | A single-transaction classifier alone can't see *sequences*; the chain-walker directly implements the definition of a peeling chain (a linear path of 2-output transactions), giving complementary, more interpretable evidence. |
| **Risk Scoring** | Personalized PageRank, seeded at the ~46 confirmed-bad wallets, over the transaction money-flow graph | Directly matches the PS's "propagate risk scores from seed illicit wallets via algorithms" instruction; PageRank is the standard propagation algorithm for this and needs no additional labels beyond the seed set. |
| **Fusion** | Weighted linear ensemble of the three scorable signals (anomaly score, classifier illicit-probability, propagated risk), each min-max normalized | Simple, auditable, and each weight can be justified/tuned rather than hidden inside a black-box model — important for the "explainable" requirement. |

## 3. Explainability method

Every alert in the ranked list carries a `reason` string built from **which
underlying signals actually fired** for that specific transaction (e.g.
*"classified as CoinJoin-like mixing (p=0.98); part of a detected multi-hop
peeling chain; broadcast from a geographically-diverse / low-reuse IP pool"*),
not just a numeric score. This is generated by simple threshold rules over
the already-interpretable model outputs (Isolation Forest's score, the
classifier's per-class probability, PageRank's propagated value, and the raw
IP-reuse/geo-diversity features) — so every claim in the reason string is
directly traceable to a specific model output, rather than a post-hoc
approximation (e.g. SHAP) of an opaque model. The dashboard's "Model
Performance" page additionally exposes ROC/PR curves, the confusion matrix,
and RandomForest feature importances for anyone who wants to audit the models
themselves.

## 4. Honest findings & known limitations

- **Entity clustering:** we directly audited the common-input-ownership
  assumption against this dataset's ground truth before trusting it, and
  found that ~99.8% of multi-input transactions in this synthetic generator
  mix addresses from *different* ground-truth entities (see notebook Section
  2). Because of this, Union-Find alone recovers almost no signal (ARI ≈ 0),
  while the graph-embedding step recovers substantially more structure
  (NMI ≈ 0.70, homogeneity ≈ 0.66, completeness ≈ 0.74). We report this
  explicitly rather than presenting an inflated number, and note that on
  traffic with a stronger co-spend signal (i.e. most real Bitcoin traffic)
  Union-Find alone typically performs far better.
- **Risk propagation:** with only 46 seed wallets (0.4% of all wallets) and a
  weakly assortative graph, propagation gives a positive but modest lift over
  the base illicit rate (wallet-level ROC-AUC ≈ 0.53–0.59 depending on
  direction/alpha) — this is expected given how little seed information is
  available, and is exactly why it's combined with the other three signals
  rather than used alone.
- **Anomaly detection** and the **mixing classifier** perform strongly on
  their own (ROC-AUC ≈ 0.77, F1 ≈ 1.00 respectively) since their target
  patterns leave a clear per-transaction statistical signature.
- **Peeling-chain detection** is the hardest sub-task (F1 ≈ 0.38 from the
  classifier alone) because a single hop looks like a normal small payment;
  the explicit chain-walk detector adds complementary, more literal evidence
  on top.

## 4b. Architecture stack

| Layer | Tool | Why |
|---|---|---|
| Ingestion | **DuckDB** | Single embedded file, zero server, queries CSV/JSON directly with SQL — the pragmatic choice for a strict offline, single-laptop constraint. `src/pipeline.py::load_data_duckdb` also runs one literal SQL query joining `transactions` (network-layer: `src_ip`, timing) with `tx_inputs`/`labels` (blockchain-layer: address, amount) — a directly inspectable artifact of the "correlates network-layer with blockchain-layer data" requirement. |
| Graph | **NetworkX** | Pure-Python, in-memory graph construction and traversal (PageRank, degree, chain-walking). |
| Anomaly detection | **scikit-learn IsolationForest** | Functionally identical to `PyOD`'s `IForest` (which itself wraps scikit-learn's implementation) — swapping in PyOD's unified API is a one-line change if you want access to its other detectors, but adds no new capability here. |
| Explainability | **SHAP** (`TreeExplainer`) | Exact, model-consistent, per-transaction feature attribution for the RandomForest pattern classifier — not an approximation. Computed live (~7ms/row) for whichever alert a judge inspects, plus a precomputed dataset-level summary over the top-500 alerts. Complements, rather than replaces, the rule-based `reason` strings (SHAP explains the *classifier*; the reason string explains the *whole ensemble*, including the two models SHAP doesn't apply to — PageRank and Isolation Forest). |
| Dashboard | **Streamlit + Pyvis** | Streamlit serves the app; Pyvis embeds an interactive, draggable vis.js network graph directly into it (`cdn_resources="in_line"`, with the two cosmetic bootstrap CDN references pyvis's default template includes stripped out) — zero external network calls, satisfying the "workable complete offline solution" requirement even for the link-analysis view. |

**Graph embeddings — a documented trade-off:** the natural choice here is
node2vec/DeepWalk. We evaluated the most common pip-installable wrapper
(`nodevectors`) and found it unmaintained — it force-downgrades `networkx` to
2.x and is broken against NumPy 2.0, which would have broken every other part
of this pipeline. Rather than fight avoidable dependency conflicts under a
hackathon deadline, we use TruncatedSVD over the address×transaction
incidence matrix instead — a standard, fast, dependency-light spectral graph
embedding (the same family of technique as NetMF) that gave strong empirical
results here (NMI ≈ 0.70). If you have time before submission and want true
node2vec, `gensim`+ a hand-rolled random-walk sampler (skip the `nodevectors`
package) is the safer path.

## 5. Reproducibility

`python src/build_artifacts.py --seed <k>` (via `generate_dataset.py --seed
<k>` on a regenerated dataset) reruns the entire pipeline deterministically.
All random states are fixed (`random_state=42`) for reproducible
train/test splits and clustering.
